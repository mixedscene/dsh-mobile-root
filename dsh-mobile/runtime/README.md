# Mobile Root Runtime

This cloud-only builder creates an ARM64 Ubuntu noble user space with Node 24.11.0, pnpm 11.28.5, Git 2.45.4 and Harness 0.2.1-alpha.2. Run `sudo bash dsh-mobile/runtime/build-runtime.sh` on a disposable native `ubuntu-24.04-arm` GitHub runner. No local SDK, compiler or runtime installation is required. The script installs build dependencies in the disposable runner and rootfs, then purges compilers and development headers before packaging. This is a real chroot user space, not a sandbox or a Bionic port.

## Outputs

The default output directory is `dsh-mobile/runtime/out`. `runtime.tar.gz` contains root-relative regular files, directories and safe backward internal hardlinks, never symbolic links. Its JSON manifest records format, build ID, SHA-256, compressed and expanded size, versions, profile and limitations. The packer resolves absolute image links against the image root, rejects parent escape and directory cycles, removes setuid/setgid bits, and caps unique regular-file bytes at 4 GiB and all entries at 500,000. Bind mounts are detached before packing; special files never enter the archive. A physical `(device, inode)` pair is written once as a regular file; every later alias points directly to that already-written regular member, never to another link. This deduplicates Git builtins and merged `/usr` file aliases without deleting required helpers. The build strips Git's main executable before installation. The Android installer must validate each hardlink target as an earlier verified regular file before calling `Os.link`; an installer accepting only files/directories must not consume this archive revision.

`runtime-sources.tar.gz` contains the pinned Git source archive and download-only corresponding Ubuntu source packages, with versions, source URLs and SHA-256 inventory. `incomplete-source-downloads.txt` lists unavailable source versions; a nonempty list means source provision is incomplete, not a successful license review. Ubuntu copyright files, Git COPYING, Node LICENSE and npm package license files are retained in the image. The npm lock records transitive tarball URLs and integrity. These GPL/LGPL/MIT and other third-party components are not relicensed as MIT; review source obligations before redistribution. Node downloads are checked against the version-specific HTTPS SHASUMS256 file; this is not independent signature verification.

## Native Contract

The supervisor binds persistent data to `/home/dsh` and temporary data to `/tmp`, and mounts `/proc` and required `/dev` files. It executes `/opt/dsh-mobile/start-mobile.sh PORT` with `HOME=/home/dsh` and `DSH_HOME=/home/dsh/.dsh`. The script seeds the mobile profile only when absent and then execs the supported `dsh --profile mobile --host 127.0.0.1 --port PORT --no-open` launcher. The usual one-time authenticated `dsh web:` URL remains on stdout; native must consume it without logging or exporting its token. Node, dsh and pnpm are under `/usr/local/bin`, and that directory must precede `/usr/bin` to select Git 2.45.4.

## Mobile Composition

`generate-mobile.mjs` compiles the repository's base and browser layers into one explicit local bundle and one mobile preset. The builder packs this bundle into an npm tarball before installing it: installing the source directory as an npm external link does not install its dependency graph. A required `npm list --all` gate rejects missing dependencies, and the normal launcher verifies installed bundle discovery. The composition removes unselected scheduling, goals, PTC/workflow, MCP, Office, embedded browser, desktop openers, telemetry and HMR rows before bundle installation, rather than hiding UI controls over an unchanged profile. It preserves file/command tools, jobs, skills, attachments, subagents, model routing, plugin management and the browser surface; adds the real terminal registry/backend/tool; and enables persistent first-search SQLite indexing. It does not implement subagent worktree allocation, Antigravity authentication, screenshots or resource-admission limits. The published CLI still carries some unused transitive dependency code; excluded plugins are not mounted, but this release does not claim a fully minimized dependency closure. Updating an already-seeded profile is deliberately not automatic in this first build.

`activity.mjs` observes the actual upstream `agent/status` and `agent/disposed` events and writes atomic, credential-free evidence to `/tmp/dsh-mobile-activity.json`. It reports `coverageComplete=false` and `freezeEligible=false` because native tasks, standalone PTYs, background jobs, indexing and plugin installation are not yet fully leased. Native must treat missing, stale or partial evidence as unknown and must not automatically freeze. Zero running agents or network silence is not an idle proof.

Auxiliary search uses the upstream `web-search-deepseek` provider with its separate `DSH_SEARCH_API_KEY` credential reference, never the chat route's `DEEPSEEK_API_KEY`. Configure a search-capable key and endpoint separately on the Plugins / Web Search settings page; the credential control follows the configured `apiKeyEnv`, and the endpoint is the provider's independent `baseURL` setting (`DEEPSEEK_SEARCH_BASE_URL` environment fallback), not the conversation Base URL. The endpoint must actually support Anthropic Messages with the native `web_search_20250305` server tool and structured result blocks; arbitrary relay or chat models are not assumed to support search. Missing credentials, unsupported search or absent structured results remain errors, never fabricated success. The unchanged upstream provider may use the native DeepSeek Account token, rather than an API key, only when a Session is explicitly on that account route and that account service authorizes the search endpoint; the dedicated-key setting is not a claim that this upstream account behavior was removed.

Sandbox policy remains `workspace-write` with approval, not automatic Full access. If the phone reports `SANDBOX_UNAVAILABLE` because Landlock/user namespaces are unavailable, command execution must fail visibly. The user may explicitly select Full access for that session after considering the risk; this removes Harness runtime-level sandbox/approval constraints, does not grant Android host root, does not make the chroot a security sandbox and does not approve native host operations. No fallback silently changes the permission mode. The mobile subagent registry permits at most two active subagents and depth one; this does not impose a global limit across multiple main sessions.

## Basic Checks

The cloud script runs Node/npm/npx/pnpm versions, Git >=2.45, a real PTY command, a sharp transform, mobile config filtering and the normal launcher boot without any API key. Regular shell wrappers for dsh, pnpm, npm and npx execute each canonical JavaScript entry path directly: flattening a Node executable symlink would otherwise change relative module resolution. After packing, the builder extracts the actual archive into a new rootfs, mounts temporary dev/proc/sys and repeats the smoke as UID/GID 65534 with fresh writable home/tmp. Only a successful artifact roundtrip writes the final validation PASS marker; roundtrip test data never enters the published image. It confirms only launcher readiness, not a model request or tool turn. The smoke masks authenticated URLs on failure and terminates its process group. Run `python dsh-mobile/runtime/test_pack_runtime.py` for small archive boundary regressions. Device root/SELinux, Android 16/17, freezer, real providers, ARM64 Android page sizes, lifecycle races and performance remain unverified until the user tests the APK. Apt and npm dependencies are recorded but are not yet reproducibly snapshot-pinned beyond the fixed top-level tool versions.
