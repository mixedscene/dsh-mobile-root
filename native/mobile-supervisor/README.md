# Android root supervisor

This executable is built by the cloud Android NDK toolchain for ARM64 and linked with a 16KB maximum ELF page alignment. It is packaged as `libmobile_supervisor.so` in the APK native library directory, but is an executable rather than a JNI library. The application invokes it only through an explicit `su -c` authorization.

`probe` requires actual UID 0 and SELinux Enforcing, reports page size, kernel, capabilities and SELinux domain, and tests private mount namespaces, propagation isolation and the chroot syscall in a separate child. KernelSU module path and cgroup-controller visibility are evidence only, not profile/freezer certification. It does not certify the installed chroot, networking, OEM background behavior or Android version support. The runtime launches in a private mount namespace with a read-only rootfs, explicit device mounts, a private devpts instance, independent writable home/tmp, UID/GID 65534, supplementary network GID 3003, empty capabilities and `no_new_privs`. SELinux policy is never changed. UID 65534 is Android's shared nobody identity, not a dedicated application sandbox; its usability and KernelSU profile behavior require device validation.

`run ROOT DATA STATE JOB OWNER_APK_PID -- COMMAND...` remains the privileged controller outside the child's process group. Java passes `android.os.Process.myPid()` explicitly, not the su daemon's parent PID. The controller opens an owner pidfd before creating a worker, verifies `/proc/OWNER_APK_PID/status` real/effective/saved/filesystem UIDs against the application-owned base directory, and rejects an already-dead/reused owner. If pidfd monitoring is unavailable or denied the runtime refuses to launch. Owner readability/hangup/error events enter the same bounded stop path, including while waiting for launch admission. This monitor does not depend on stdin, which ordinary command/file transfers may close normally. The controller blocks on its owner pidfd, private control FIFO and signal pipe without periodic keep-alive polling. The child's parent-death guard independently handles controller death.

The FIFO accepts stop/freeze/thaw requests. Stop resumes a stopped group, requests TERM, escalates to KILL after five seconds, allows two seconds for the main child to exit, and performs bounded adopted-descendant reaping for three seconds. Uninterruptible tasks cannot make the controller wait forever: they result in unresolved cleanup instead. Adopted direct children are discovered through the controller's own proc children file and killed using pidfds where supported, without an unsafe numeric-PID fallback. The main PID remains unreaped until group signalling completes, preventing PID reuse during cleanup. Stop deadlines use a monotonic clock. The child namespace's mounts are destroyed when all users exit. Force-killing the controller itself still cannot certify all escaped descendants; complete cgroup containment remains outside this first implementation.

Java confirms the root-owned FIFO with `control STATE JOB ready` before the controller creates any worker. The native controller waits at most fifteen seconds for this admission message, so short-lived commands cannot finish before their control channel is confirmed. A missing readiness message creates no runtime worker. Launch and the full stop/recovery scan share one Java monitor; an admission epoch rejects commands queued across a stop, and unconfirmed stop results keep new launches blocked until an explicit successful Stop/recovery. The parent-death SIGKILL guard is restored after the final UID/GID transition, which would otherwise clear it, and the worker verifies its captured controller PID before executing runtime code.

Freeze/thaw currently uses SIGSTOP/SIGCONT on the process group, not cgroup freezer. There is no freezer acknowledgement. A descendant that creates another process group or namespace may escape signal-group cleanup. Unreaped descendants produce exit code 79 and a persistent `.unresolved` state marker; cleanup is explicitly unknown. Full descendant containment and safe automatic background freezing are not implemented; the UI must not report this fallback as verified tombstone-style freezing, and must not freeze on guessed activity. No shell, plugin or command receives a generic root execution bridge.

Unresolved controller evidence is preserved by atomically renaming the existing FIFO to its `.unresolved` name before closing it. Rename failure retains the original FIFO rather than exposing an empty state directory. The state directory is synced after the rename; failure still reports cleanup unknown. The retained FIFO is evidence, not a live recovery endpoint.

`check-state STATE` refuses a new Java runtime instance while previous controller evidence remains. `stop-all STATE` can request bounded shutdown of living prior controllers even after the app's in-memory process map is lost. Stale FIFOs and unresolved descendants are not silently deleted and require explicit manual recovery; full automatic crash recovery is not implemented. `RootRuntime.cancel(Context, Process)` stops one registered command and checks cleanup independently of the Web service. Callers must not substitute `Process.destroy()` for confirmed runtime cleanup.

`install STAGING BASE` rejects an existing runtime, recursively rejects symlinks/devices, applies root ownership, initializes independent nobody-owned home/tmp, and atomically renames the verified stage to `BASE/rootfs`. The Java installer checks `assets/runtime/runtime.tar.gz` SHA-256 against `assets/runtime/runtime-manifest.json`, accepts regular files/directories and confined backward hard links within 4GiB/500000-entry budgets, rejects traversal and duplicate entries, syncs extracted files, and creates required device mountpoint files. Hard-link names must be normal relative paths referring to an earlier fully extracted regular-file entry; forward targets, directories, symlinks, hard-link chains, self-links, external paths and nonzero link payloads are rejected. Only successful regular-file extractions enter the hard-link source set. `Os.link` creates a new destination without overwriting, and link entries never change shared inode permissions. Hard links count toward the entry budget but do not duplicate expanded-byte accounting. The installer manifest path is reserved and cannot be supplied by the archive. The APK signature is the authenticity source; the manifest is not an independently downloaded signing authority. Interrupted pre-commit installations may require explicit staging recovery; cleanup failures are attached to the original error, not reported as successful cleanup. Automatic upgrades/rollback and reinstall of an existing rootfs are deliberately refused rather than silently overwriting data.

Installed runtime recognition requires the saved manifest to match the APK's bundled manifest byte-for-byte, including its build ID and archive hash. An upgraded APK must not label an older rootfs verified or silently run it; mismatches require explicit migration/recovery and preserve the existing rootfs/data. Stop/recovery remains available independently of whether the old runtime matches the current APK.

Before launching, Java obtains numeric DNS servers from Android's active `ConnectivityManager` network and atomically writes the private `mobile/resolv.conf`. Configured DNS produces only validated `nameserver` lines, at most three servers, preserving numeric IPv6 scope IDs. No active network or an empty DNS list instead produces an explicit offline comment and `options timeout:1 attempts:1`, without inventing any nameserver; local runtime, Git and files remain launchable. CI/public resolver addresses are never a fallback. Permission failures, inspection errors and invalid DNS addresses still fail explicitly. `RootRuntime.resolverStatus()` exposes the committed resolver state; the service includes its launch snapshot in Running/Ready status, including `Offline/no DNS; network calls unavailable, restart after connecting`. This does not certify online functionality or enforce a complete network sandbox. The native child opens the fixed file with `O_NOFOLLOW`, requires a bounded regular file, and bind-mounts the opened descriptor read-only only onto the regular `rootfs/etc/resolv.conf`. No host directory is exposed. Already-running namespaces retain their resolver snapshot: after network, VPN or DNS changes the user must explicitly stop and restart the runtime. Android Private DNS/VPN policies, UID 65534 network permissions and glibc DNS/TLS still require device verification.

The service publishes a token-bearing launch URL only on the main thread while the emitting `Process` remains its current owner and stop/destruction has not begun. Old output/exit callbacks cannot mark a new generation ready, and raw stdout/token URLs are not added to diagnostics or notifications.

Cloud build and native static checks are separate from device acceptance. Real KernelSU/SELinux Enforcing launch, DNS/TLS, Node native addons, 4KB/16KB library loading and stop/mount cleanup remain unverified until a user device run.

Basic cloud checks are `bash native/mobile-supervisor/test-host.sh` and Gradle `:app:testDebugUnitTest`. Host tests compile the helper, exercise non-root/invalid-argument refusals, perform a host UID/GID-drop parent-death test, check FIFO readiness/atomic unresolved evidence, and kill a fake APK owner with a distinct UID to verify its pidfd death event enters bounded managed-worker cleanup. Pure Java unit tests exercise the installer's path/entry/expansion/hash/manifest and confined hard-link validation, stop admission epochs, failed-stop fencing and numeric DNS formatting. These checks do not substitute for Android ARM64 privilege-drop, PTY, service lifecycle or runtime launch acceptance.
